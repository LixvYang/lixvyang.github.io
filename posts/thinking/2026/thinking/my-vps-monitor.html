    # 一台 $20 的 VPS，养着我的数字乐园

    以前我的服务挂了，是用户来告诉我的。现在是手机先响。

    上一篇写了怎么把十几个服务搬进一台 VPS。搬完之后，我又在这台机器上陆续搭了一圈"看不见的东西"：门禁、告警、定时任务监控、整机备份、导航页。它们不直接产生价值，但有了它们，这台机器才算真正能放心交出去。

    这篇记录一下，我是怎么用一堆开源服务，把一台小 VPS 打理成一个自己的数字乐园的。

    文中的域名、IP、密钥都用占位符代替。

    # 全景

    先看一眼现在这台机器上都有什么：

    层用什么干什么
    部署Coolifyopen in new window所有应用和数据库，push 代码自动部署
    门禁Cloudflare Zero Trust管理后台要先登录，服务器只认 Cloudflare 来的流量
    监控UptimeFlareopen in new window、Beszelopen in new window服务在不在线；CPU、内存、磁盘
    定时任务Healthchecksopen in new window每天的备份、重启、清理有没有按时跑
    告警ntfyopen in new window上面所有告警汇到一个地方，推到手机
    备份Coolify 自带、Backrestopen in new window数据库、密码库、整机配置，每天加密传到 R2
    入口Glanceopen in new window一个导航页，看一眼就知道全局
    统计Umamiopen in new window网站访问统计
    密码Vaultwardenopen in new window自建的 Bitwarden

    全部是开源软件，除了 VPS 本身每月 $20，没有多花一分钱。R2 用的是免费额度。

    # 门禁：后台只有我能进

    Coolify 面板、状态页、导航页、备份管理页，这些地方只有我自己需要看，没必要对整个互联网开放。

    我的做法是三层：

    1. 域名开 Cloudflare 代理（橙色云朵），流量先过 Cloudflare。
    2. 加一层 Zero Trust Access。 打开页面先跳到 Cloudflare 的登录页，用 GitHub 账号或者邮箱验证码登录，名单里只有我自己的几个邮箱。免费版 50 人以内不收钱。
    3. 服务器只认 Cloudflare 的 IP。 不然别人知道了服务器 IP，绕过 Cloudflare 直接连，前两层就白搭了。我在 Traefik 里加了一个 ipAllowList 中间件，只放行 Cloudflare 公布的 IP 段，直连一律 403。

    有两个地方要特意放行：Coolify 的 /webhooks（GitHub 推代码后通知部署）和 /api（CI 和我自己调接口）。GitHub 没法帮你登录 Zero Trust，这两个路径要单独设成"免登录"。它们本身有签名或 Token 校验，不会因此变得不安全。

    坑：Docker 映射出去的端口会绕过 ufw。 ufw status 显示只开了 22，但 Coolify 的 8000 端口其实一直对公网开着，任何人都能打开登录页。要在 DOCKER-USER 链里单独挡掉，并且写成开机自动执行。

    # 告警：所有声音汇成一条河

    监控工具我装了好几个，但手机上只装一个 App：ntfy。

    ntfy 是一个极简的推送服务：往一个地址 POST 一段文字，手机就会收到通知。我自建了一个，关掉注册、默认谁都不能读写，只建了两个账号：一个给手机看，一个只能往 alerts 主题里写，给各个监控工具用。

    现在往这条河里汇水的有四个源头：

    谁什么时候响
    UptimeFlare某个网站打不开，或者恢复了
    Beszel服务器离线；CPU、内存连续 10 分钟超过 90%；磁盘超过 85%
    Healthchecks某个定时任务没按时跑，或者跑失败了
    Coolify部署失败、备份失败、容器挂了、服务器连不上

    几个小技巧：

    • UptimeFlare 跑在 Cloudflare Workers 上，不在被监控的机器上。服务器整台挂了，它照样能发出告警。
    • ntfy 的 token 不要写进仓库。 我在 GitHub Actions 部署时用 secret 替换配置里的占位符。
    • Coolify 的 webhook 不能自定义请求头，就把 token 放进 URL 的 auth= 参数里，再用 ntfy 的消息模板把 JSON 渲染成人能读的标题和正文。
    • iOS 的即时推送要设置 upstream-base-url: https://ntfy.sh。只会把消息 ID 发给官方服务器，内容不会经过它。

    # 定时任务：没响也是一种告警

    服务挂了会报错，但定时任务没跑，是不会报错的。备份脚本因为某次改动悄悄不执行了，你可能要等到真正需要恢复的那天才知道。

    Healthchecks 解决的就是这个问题，思路叫"死人开关"：每个任务跑完都要来"打个卡"，到点没打卡就告警。

    我写了一个很小的包装脚本 hc-run，任何定时任务套一层就行：

    #!/bin/sh
# 用法：hc-run <检查名> <命令...>
slug=$1; shift
url="https://hc.example.com/ping/$(awk -v s="$slug" '$1==s{print $2}' /root/.secrets/hc-checks)"
curl -fsS -m 10 -o /dev/null "$url/start"
out=$(mktemp); "$@" >"$out" 2>&1; rc=$?
cat "$out"
tail -c 10000 "$out" | curl -fsS -m 10 -o /dev/null --data-binary @- "$url/$rc"
rm -f "$out"; exit $rc

    它会上报开始、退出码和最后一段输出，失败时在通知里就能直接看到报错。

    现在被盯着的任务有：每天重启一个吃内存的前端、清理过期的快照数据、备份密码库、导出数据库、整机备份，还有一个专门检查"Coolify 的数据库备份到底有没有成功传到 R2"的任务。

    坑：Coolify 的定时任务按服务器时区（UTC）跑，不是你在设置里选的时区。我一开始以为备份在凌晨，其实是中午。Healthchecks 里每个检查的时区要对上，不然会天天误报。

    # 备份：三层，而且要能解开

    内容怎么备份保留
    PostgreSQLCoolify 自带的定时备份，pg_dumpall 传到 R230 份
    密码库自己写的脚本：SQLite 在线 .backup，先做完整性检查再上传30 天
    整台机器的配置和密钥Backrest（restic 的网页版），加密、增量、去重日 14 / 周 8 / 月 6

    前两层是"数据"，第三层是"环境"：/etc 里的防火墙规则和定时任务、我写的脚本、Coolify 自己的配置和主密钥、各个服务的数据卷、所有自动生成的密码。服务器真没了，有这一份就能照着重建。

    几个经验：

    • Vaultwarden 的数据不在数据库备份里。 它用的是 SQLite，存在 Docker 数据卷中，Coolify 不会备份它。我检查的时候才发现，自己的密码库其实一直在裸奔。
    • 运行中的数据库不要直接拷文件。 先 pg_dumpall 导出成文件，再让 Backrest 备份导出文件，恢复时才可靠。
    • 加密备份的密码一定要另存一份。 restic 的仓库密码只在服务器上的话，服务器一丢，R2 里的备份也就打不开了。一定要在密码库里另存一份。
    • 上传完要验证。 第一次备份完，我把快照里的文件列表列出来对了一遍，确认密钥、数据库导出都在里面。

    # 导航页：一眼看全局

    服务多了，光记地址就够累的。我用 Glance 做了一个导航页：

    • 中间是所有服务的在线状态和响应时间，每分钟刷新；
    • 左边是时钟（服务器所在时区、UTC、另一台机器所在时区）、加密货币行情、各个平台后台的入口；
    • 右边是这些开源软件的最新版本，方便判断要不要升级；
    • 顶部一个搜索框，按 S 聚焦，!gh 搜 GitHub、!bd 搜百度。

    Glance 只占 13M 内存，整个页面就是一个 YAML 文件，改完保存几秒自动生效。

    默认样式是全等宽字体，中文显得歪歪扭扭。我加了一个自定义 CSS：正文换成 Inter 加系统中文字体，数字保留等宽；卡片改成大圆角、半透明、柔和阴影；再配一套明暗主题。改动不大，观感差别很明显。

    坑：

    • Yahoo 的加密货币 24 小时涨跌一直显示 0%，我把行情换成了 CoinGecko 的免费接口，用 Glance 的 custom-api 组件自己写模板。
    • CoinGecko 的图片 CDN 在国内打不开，币种图标要下载到服务器上自己托管。
    • Glance 模板读数字时，YAML 里的整数会被当成 0，要写成 60.0 这种小数。

    # 访问日志：没有日志，出事就是瞎子

    有一次排查一个公开的高危漏洞，想确认自己的服务有没有被打过，结果发现 Traefik 根本没开访问日志，只能靠别的痕迹间接判断。

    于是我开了访问日志：JSON 格式，只留 User-Agent 和 Cloudflare 传过来的访客真实 IP，其他请求头全部丢掉。每天大约 40M，保留 7 天，压缩后一共不到 100M。

    日志里会有带 token 的 URL，所以它只有 root 能读，也不进备份。

    坑：改 Coolify 的代理配置不要直接 docker compose up 重建容器。 重建后 Traefik 只连着主网络，各个服务自己的 Docker 网络全断了，好几个服务挂了三分钟。要通过 Coolify 的界面或者它的保存函数来改，它会把网络重新接好。

    # 给 AI 留一份说明书

    这些东西大部分是 Claude Code 帮我搭的。问题是：下次换一个会话，或者换一个 AI，它什么都不知道，很容易重复踩坑，甚至把之前的配置改坏。

    所以我在服务器上放了一份 /root/AGENTS.md，再链接一份 CLAUDE.md，这是很多 AI 编程工具约定俗成的说明书文件名。SSH 登录时还会多一行提示：「先读 /root/AGENTS.md，改动后请更新它。」

    里面写着：

    • 硬性规矩：不能打印密钥、不开云厂商的备份、往个人仓库提交只能用匿名邮箱；
    • 每个服务的位置、域名和内存上限；
    • 告警和备份链路；
    • 每种密钥放在哪个文件里（只写位置，不写内容）；
    • 踩过的十几个坑；
    • 待办，以及变更记录。

    这份文件对人也一样有用。半年后的我，大概也不记得当初为什么要加那条防火墙规则了。

    # 第二台机器也管起来

    我还有一台跑代理的小机器，1G 内存。它也接进了这套体系：

    • Beszel 的 agent 装成一个 systemd 服务，主动连回东京的 hub，不用在小机器上开任何端口；
    • 加进了 Coolify，但代理类型设成 None，因为 443 已经被代理程序占了，不能再让 Coolify 装 Traefik；
    • 它离线、磁盘快满时，同样推到 ntfy。

    # 资源和成本

    服务内存
    ntfy15M
    Beszel14M（agent 另 5M）
    Glance13M
    Backrest11M
    Healthchecks150M
    Umami240M

    这一整圈"看不见的东西"加起来不到 500M。整台机器（2 核 4G）跑着十几个业务服务再加上它们，内存用了一半多一点，CPU 负载不到 1。

    额外花费：0。

    # 最后

    搬家那一篇解决的是"放在哪"，这一篇解决的是"放心交出去"。

    我的感受是，自托管真正的成本从来不是那 $20，而是你需要随时惦记着它。这一圈服务做的事情，就是把"惦记"这件事外包出去：网站挂了有人喊，任务漏了有人喊，数据丢了有备份，忘了怎么回事有说明书。

    现在大部分时候，我已经不用去看它了。手机不响，就说明一切正常。
